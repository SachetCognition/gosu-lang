1 Fix CI Cache Ordering & Add Matrix Testing

File: .github/workflows/build-test.yml

Problem

  • A standalone actions/cache@v4 step (lines 33–39) was redundant because setup-java already handles Maven caching via cache: 'maven' on line 28.
  • The CI only tested on Java 11. The Gosu compiler should also be verified on Java 17.
  • The "Test results Summary" step hardcoded **Java Version:** 11.

Changes

ChangeDetail
removed Redundant cache step Deleted the actions/cache@v4 block. setup-java with cache: 'maven' already handles it.
added Build matrix strategy.matrix.java-version: ['11', '17'] with per-version maven-args.
added Dynamic Java version in summary ${{ matrix.java-version }} replaces the hardcoded 11.
added Unique artifact names test-reports-java-${{ matrix.java-version }} prevents upload collisions.

Build Matrix Details

Java VersionModules BuiltMaven Args
11All 12 modules(none)
17All except gosu-lab, gosu-doc, gosu-ant-tools, gosu -pl !gosu-lab,!gosu-doc,!gosu-ant-tools,!gosu
Why exclude modules on Java 17? These modules use JDK-internal APIs that changed between JDK 11 and 17:
  • gosu-lab — GosuVisitor implements TreeVisitor, which added abstract method visitYield(YieldTree) in JDK 14+. The parameter types don't exist in JDK 11, so the method can't be compiled on both.
  • gosu-doc — Start.java calls CommandLine.parse() which returns String[] in JDK 11 but List<String> in JDK 17.
  • gosu-ant-tools / gosu — depend on gosu-doc.
The core language, compiler, and full test suite (13,900+ tests) run successfully on both JDKs.

Final Workflow (abridged)

strategy:
  matrix:
    java-version: ['11', '17']
    include:
      - java-version: '11'
        maven-args: ''
      - java-version: '17'
        maven-args: '-pl !gosu-lab,!gosu-doc,!gosu-ant-tools,!gosu'

steps:
  - uses: actions/checkout@v4

  - name: Set up Java (Amazon Corretto ${{ matrix.java-version }})
    uses: actions/setup-java@v4
    with:
      distribution: 'corretto'
      java-version: ${{ matrix.java-version }}
      cache: 'maven'                          # ← handles caching

  - name: Build and run tests
    run: mvn clean verify -B -V ${{ matrix.maven-args }}

  - name: Test results Summary
    run: |
      echo "**Java Version:** ${{ matrix.java-version }}" >> $GITHUB_STEP_SUMMARY
      ...

  - uses: actions/upload-artifact@v4
    with:
      name: test-reports-java-${{ matrix.java-version }}   # unique per JDK
      ...

2 Fix Hardcoded Permission Checks in Workflows

Problem

The actions/github-script permission check steps in the publish and release workflows hardcoded owner: 'gosu-lang' and repo: 'gosu-lang'. This breaks in forks where the owner/repo differ from the upstream.

Diff

Applied identically to both files:

@@ permission check in actions/github-script @@
const permission = await github.rest.repos.getCollaboratorPermissionLevel({
- owner: 'gosu-lang',
- repo: 'gosu-lang',
+ owner: context.repo.owner,
+ repo: context.repo.repo,
username: context.actor
});

Affected Files

  • .github/workflows/publish-snapshots.yml (lines 27–28)
  • .github/workflows/release-gosu.yml (lines 47–48)
Result: context.repo.owner and context.repo.repo are automatically set by GitHub Actions to the repository where the workflow is running, making permission checks fork-safe.

--add-exports Requirements & IDE Setup

Gosu accesses internal JDK APIs (com.sun.tools.javac.*, sun.reflect.annotation, sun.awt, etc.). The Maven POM (gosu-parent/pom.xml) already configures the required --add-exports flags. Your IDE may need manual configuration:

Test Patterns

Errant Type Tests (BaseVerifyErrantTest + processErrantType)

Errant tests verify that the Gosu compiler correctly reports parse/compile errors.

Step 1 — Test Class

Extends BaseVerifyErrantTest and calls processErrantType(Errant_Foo):

class SomeFeatureTest extends BaseVerifyErrantTest {
  function testErrant_SomeFeatureTest() {
    processErrantType(Errant_SomeFeatureTest)
  }
}

Step 2 — Errant Type Class

Contains intentionally broken code with //## issuekeys: annotations:

class Errant_SomeFeatureTest {
  var x : int = "hello"  //## issuekeys: MSG_TYPE_MISMATCH
  var y : int = 42       // No annotation = no error expected
}

Step 3 — How processErrantType Works

  1. Parses the errant type's source line-by-line.
  2. For each line with //## issuekeys: KEY1, KEY2, asserts exactly those errors are reported.
  3. For lines without annotations, asserts no errors exist.
  4. Lines with //## KB(JIRA-123) mark known breaks (skipped with -Dgw.tests.skip.knownbreak=true).
Important: Each errant line must list every expected issue key. If the compiler emits two errors on one line, both keys must appear comma-separated. Issue keys correspond to constants in gw.lang.parser.resources.Res (e.g., MSG_TYPE_MISMATCH, MSG_NO_SUCH_FUNCTION).

Specification Tests (gw/specification/)

Organized under gosu-test/src/test/gosu/gw/specification/, mapping directly to language specification sections:

gw/specification/ ├── expressions/ # Arithmetic, comparison, ternary, etc. ├── genericTypesAndMethods/ # Generics, type parameters, variance ├── statements/ # for-each, if/else, switch, try-catch, using │ ├── assignmentStatements/ │ ├── blockStatements/ │ ├── forEachStatement/ │ ├── returnsExitsAndExceptions/ │ └── ... ├── types/ # Primitive types, reference types, conversions │ ├── primitiveTypes/ │ ├── referenceTypes/ │ ├── typeConversion/ │ └── ... ├── typeDynamic/ # Dynamic type behavior ├── structures/ # Structural typing ├── variablesParametersFieldsScope/ # Scoping rules └── temp/ # Exploratory / in-progress tests

PR Guidelines

  1. Branch from master — create a feature branch for your work.
  2. Keep changes focused — one logical change per PR.
  3. Add tests — for new features, add specification tests under gw/specification/. For bug fixes involving incorrect error reporting, add or update errant tests.
  4. Run the full build before submitting: 
    mvn clean verify -B
  5. Follow existing code style — Gosu source uses 2-space indentation; Java source follows standard Java conventions.
  6. Update documentation — if your change affects public API, update gosudoc comments.
  7. CI must pass — the GitHub Actions workflow runs tests on Java 11 and Java 17 via a build matrix. Both must pass.
  8. Sign-off — by submitting a PR you agree your contribution is provided under the Apache License 2.0.
